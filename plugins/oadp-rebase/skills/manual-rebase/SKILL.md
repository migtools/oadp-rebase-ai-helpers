## Name
oadp-rebase:manual-rebase

## Synopsis
```
/oadp-rebase:manual-rebase <repo> <branch> [--reason <reason>]
```

## Description
The `oadp-rebase:manual-rebase` command provides step-by-step guidance for manually rebasing repositories that cannot be handled by the automated rebasebot process. Some repos consistently need manual intervention due to architectural issues.

### When Manual Intervention is Needed

1. **Stale rebase branch problem**: When rebasebot detects "dest already contains source" (because the upstream tag hasn't changed), it may reuse an existing stale rebase branch as the base instead of the current dest branch. This causes downstream-only files to be dropped because the stale branch predates their addition.

2. **Conflict policy blocking**: When `--conflict-policy strict` blocks the rebase because hook-generated `UPSTREAM: <drop>` commits modify files (go.mod/go.sum) that differ between upstream versions. The strict policy treats this as "content loss" even though the content is regenerated by hooks.

3. **hypershift-oadp-plugin**: This repo uses a manual process - update go.mod replace directive to point to the latest downstream velero commit, run `go mod tidy && go mod vendor`, and create a PR manually.

4. **Cherry-pick conflicts**: When downstream carry commits conflict with upstream changes that cannot be auto-resolved.

### Known Problematic Repositories

- **kubevirt-velero-plugin**: Frequently hits stale rebase branch problem. Has many downstream-only files (Dockerfile.ubi, konflux.Dockerfile, release-announcement).
- **hypershift-oadp-plugin**: Always manual. Not included in wave automation. Requires updating go.mod replace directive for `github.com/openshift/velero`.
- **oadp-operator**: Hooks-only repo that can fail if velero CRD copy hook can't find the correct velero branch.

## Implementation

### Phase 0: Set Up the oadp-rebase Repository
All strategies below require the oadp-rebase repo for configs and hook scripts. Do NOT rely on it being in the current working directory or home directory. Re-use a previous clone if available, otherwise clone fresh:
```bash
OADP_REBASE_DIR="/tmp/oadp-rebase-tools"
if [ -d "$OADP_REBASE_DIR/.git" ]; then
  cd "$OADP_REBASE_DIR"
  git fetch origin
  git reset --hard origin/oadp-dev
else
  git clone https://github.com/oadp-rebasebot/oadp-rebase.git "$OADP_REBASE_DIR" --branch oadp-dev --single-branch
  cd "$OADP_REBASE_DIR"
fi
```
Config files are in `$OADP_REBASE_DIR/rebase-configs/` and hook scripts in `$OADP_REBASE_DIR/rebasebot-hook-scripts/`.

### Strategy A: Stale Rebase Branch Fix
When rebasebot drops downstream files due to stale rebase branch:

1. **Delete the stale remote rebase branch**:
   ```bash
   gh api -X DELETE repos/oadp-rebasebot/{repo}/git/refs/heads/rebase-bot-{branch}
   ```

2. **Clone the dest branch into a unique temp directory**:
   ```bash
   WORK_DIR="/tmp/oadp-rebase-manual-$(date +%Y%m%d-%H%M%S)"
   mkdir -p "$WORK_DIR"
   git clone https://github.com/{dest-org}/{repo}.git "$WORK_DIR/{repo}"
   cd "$WORK_DIR/{repo}"
   git checkout {branch}
   ```

3. **Run hooks manually**:
   ```bash
   export REBASEBOT_SOURCE="https://github.com/{upstream-org}/{repo}:{tag}"
   export GIT_USERNAME="oadp-team-rebase-bot"
   export GIT_EMAIL="oadp-maintainers@redhat.com"
   # Run each hook script in order:
   ./path/to/go-replace_velero_{branch}.sh
   ./path/to/go-mod-tidy-and-commit.sh
   ./path/to/normalize-dockerfiles-and-commit.sh
   ```

4. **Push to rebase branch and create PR**:
   ```bash
   git remote add rebase https://github.com/oadp-rebasebot/{repo}.git
   git push rebase HEAD:rebase-bot-{branch} --force
   gh pr create --repo {dest-org}/{repo} \
     --base {branch} \
     --head oadp-rebasebot:rebase-bot-{branch} \
     --title "Rebase {repo} to {tag}" \
     --body "Manual rebase to {tag}"
   ```

### Strategy B: Conflict Policy Override
When strict conflict policy blocks the rebase:

1. **Identify the conflicting commits**: Look at the rebasebot error output for which `UPSTREAM: <drop>` commits are flagged
2. **Verify the flagged content is regenerated by hooks**: Check if the "lost" go.mod/go.sum lines are upstream transitive dependencies that `go mod tidy` will regenerate
3. **Temporarily add `--conflict-policy warn`** to the config's `EXTRA_REBASEBOT_ARGS`:
   ```bash
   EXTRA_REBASEBOT_ARGS="--always-run-hooks --conflict-policy warn"
   ```
4. **Run the rebase**
5. **REVERT the conflict-policy change** after the rebase completes - do not leave `warn` in the config permanently
6. **Verify all carry commits are preserved** using `/oadp-rebase:verify-commits`

### Strategy C: hypershift-oadp-plugin Manual Update
1. **Find the latest downstream velero commit**:
   ```bash
   gh api repos/openshift/velero/commits?sha=oadp-1.6&per_page=1 | jq -r '.[0].sha'
   ```
2. **Calculate the go pseudo-version**:
   ```bash
   WORK_DIR="/tmp/oadp-rebase-hypershift-$(date +%Y%m%d-%H%M%S)"
   git clone https://github.com/openshift/hypershift-oadp-plugin.git "$WORK_DIR"
   cd "$WORK_DIR"
   # Update go.mod replace directive. Check which module path the project uses:
   grep "velero" go.mod | head -5
   # Use the matching path (vmware-tanzu or velero-io) on the left side:
   # {module-path} => github.com/openshift/velero v0.10.2-0.{date}-{commit12}
   go mod edit -replace github.com/vmware-tanzu/velero=github.com/openshift/velero@{commit}
   go mod tidy
   go mod vendor
   go vet ./...
   ```
3. **Create the PR**:
   ```bash
   git checkout -b update-velero-{version}
   git add -A
   git commit -m "UPSTREAM: <carry>: update velero dependency to {version}"
   git push origin update-velero-{version}
   gh pr create --base main --title "Update velero dependency to {version}"
   ```

## Return Value
- Step-by-step instructions customized for the specific repository and failure mode
- Commands ready to copy-paste for manual execution

## Examples

1. **Fix kubevirt-velero-plugin stale branch**:
   ```
   /oadp-rebase:manual-rebase kubevirt-velero-plugin oadp-1.6 --reason stale-branch
   ```

2. **Handle conflict policy blocking on AWS plugin**:
   ```
   /oadp-rebase:manual-rebase velero-plugin-for-aws oadp-1.6 --reason conflict-policy
   ```

3. **Update hypershift-oadp-plugin**:
   ```
   /oadp-rebase:manual-rebase hypershift-oadp-plugin oadp-1.6
   ```

## Arguments
- `$1`: Repository name
- `$2`: OADP branch
- `--reason`: Optional reason hint: `stale-branch`, `conflict-policy`, `cherry-pick-conflict`, or auto-detected
